# NCC 사용 설명서 만들기

독자는 제품을 처음 쓰는 현장 관제사·운영자다. 개발자가 아니다. 목표는 "화면의 각 영역을 어떻게 보고, 언제 무엇을 누르면 되는지"를 알려 주는 것.

## 사이트 구조

```
public/
  index.html        브라우저 언어에 따라 /ko/ 또는 /en/으로 이동
  ko/index.html     한국어판
  en/index.html     영어판 (한국어판에만 있는 기능은 빠질 수 있음)
  assets/manual.css 공통 스타일
  assets/manual.js  페이지 이동 · 검색 · data-to 스크롤 (페이지 수는 자동 계산)
  assets/img/       이미지. 파일명 = 내용 sha1 앞 12자리 + 확장자
vercel.json         public/을 그대로 배포. main에 push하면 Vercel이 자동 배포
```

- 한 페이지 = `<section class="page" id="pN" data-ch="03" data-title="…">`. 사이드 메뉴 링크 `<a href="#pN" data-page="N">`와 짝을 맞춘다.
- 페이지 안 = 제목(`.eyebrow`, `h1`, `.sub`) → 카드(`section.card`) → 이미지(`.figwrap > .fig`) → 번호 설명(`.rows > .row`).
- 표지(p1)에는 장 바로가기(`.jump`)와 업데이트 내역 표(`section.updates`)가 있다.

## 작업 순서

1. **자료 확인** — Figma는 `get_metadata`로 텍스트 레이어를 뽑고 `get_screenshot`(필요하면 `enableBase64Response`)으로 화면을 본다. Claude Design / Artifact 링크는 Artifact `read`로 데이터 파일(JSON)과 이미지를 받는다. 자료에 없는 동작은 지어내지 않는다.
2. **위치 정하기** — 기존 장에 카드로 붙일지, 새 장을 만들지 정한다. 중간에 새 페이지를 끼우면 뒤 페이지 번호와 모든 `#pN` 링크가 밀리므로, 새 장은 맨 뒤에 붙이거나 기존 페이지에 카드로 넣는다.
3. **한국어판 · 영어판 모두 수정** — 사용자가 한쪽만 말하지 않는 한 둘 다. 영어판에 없는 기능(예: 엘리베이터)은 넣지 않는다.
4. **확인** — `cd public && python3 -m http.server`로 띄우고 Playwright로 해당 페이지 캡처, 깨진 이미지 0개, 링크 이동을 확인한다. 캡처를 사용자에게 보여 준다.
5. **커밋 · push** — main에 push하면 바로 공개된다. 사용자가 공개를 원하지 않으면 브랜치에만 올린다.
6. **보고** — 바꾼 것, 추측해서 쓴 문장, 확인하지 못한 것을 따로 적는다.

## 번호 태그(핫스팟)

- 이미지 위 번호와 아래 설명 번호를 똑같이 맞춘다. 장 번호 기준: 02장 → `1-1`, `1-2`… / 03장 → `2-1`… 처럼 기존 규칙을 따라 이어 붙인다. 기존 번호는 밀지 않는다(필요하면 `4-0`처럼 앞에 붙인다).
- 위치는 이미지 픽셀 좌표를 퍼센트로 바꿔 넣는다:
  `<span class="hot l" data-n="3-6" style="left:x0/W%;top:y0/H%;width:(x1-x0)/W%;height:(y1-y0)/H%"></span>`
- 라벨 위치 클래스: `t` 위, `b` 아래, `l` 왼쪽, `r` 오른쪽, `in` 안쪽 왼쪽 위. 다른 요소를 가리지 않는 쪽을 고른다.
- 좌표는 이미지를 직접 보고 잡고, 렌더링 캡처로 어긋났는지 확인한다.

## 이미지

- 언어별 화면을 쓴다. 영어 이미지가 없으면 한국어 이미지를 쓰고 사용자에게 알린다.
- 영어 화면이 따로 있고 레이아웃이 같으면, 바뀐 영역(예: 카메라 영상)만 한국어 이미지에서 잘라 영어 화면에 합성할 수 있다. 합성 영역 안의 한국어 글자(예: 화질 '중간')는 영어 화면의 글자로 덮는다.
- Figma 카드처럼 배경이 투명한 이미지는 어두운 배경(#262626, 여백 10px)에 얹어 저장한다.
- 저장: `public/assets/img/<sha1 12자리>.<png|jpg|webp>`. 큰 스크린샷은 JPEG/WebP.

## 문체

- 사용자가 주어인 안내체: "~를 누르세요", "~하면 ~됩니다".
- 개발용 정보는 넣지 않는다: 픽셀 값, 코드명, 말줄임 규칙, stroke·opacity 같은 용어.
- 쉬운 말로: stroke → 테두리, disable → 누를 수 없음, 로컬패스 → 경로.
- 버튼 이름은 실제 화면 문구 그대로 `[Save]`, `[로봇 재부팅]`.
- 상태별 색은 색 점 태그 `<span class="cchip" style="--c:#EF8A43">주의</span>`, 색 코드는 보이지 않게.
- 개념 설명과 상태 설명이 섞이면 표로 나눈다. 알림 코드처럼 찾아볼 값은 표로.
- 주의 사항은 `<div class="info warn">` 박스로 짧게. 이모지 금지.
- 한국어 · 영어 모두 단어 단위 줄바꿈(CSS `word-break:keep-all`이 이미 적용됨).

## 업데이트 내역 (표지)

- 사용자가 넣어 달라고 한 항목만 넣는다. 자동으로 추가하지 않는다. 새 항목은 표 맨 위.
- 행 형식: `<tr><td class="n">YYYY.MM.DD</td><td><a href="#pN" data-to="<카드 id>">NN 장 이름</a></td><td><b>기능명</b> 추가 (번호 범위)</td></tr>`
- `data-to`에 새 카드의 `id`를 주면 그 카드로 스크롤 후 잠깐 강조된다. 새 카드에는 `id`를 붙인다.
- 항목을 넣을 때 표지 아래 `문서 갱신` / `Last Updated` 날짜도 맞춘다.

## 배포 미루기 · 다시 올리기

- 숨기기: 현재 main을 `<기능명>` 브랜치로 push해 보관한 뒤, main에서 해당 커밋들을 `git revert` 하고 push. 업데이트 내역 행과 갱신일도 함께 되돌아가는지 확인.
- 다시 올리기: 보관 브랜치의 커밋을 main에 cherry-pick(또는 revert의 revert)하고, 업데이트 내역 날짜와 갱신일을 실제 배포일로 고친다.

## 하지 말 것

- 자료에 없는 기능·수치·동작을 사실처럼 쓰기. 추측은 보고에서 따로 밝힌다.
- 한쪽 언어만 고치고 말없이 끝내기.
- 확인하지 않은 것을 확인했다고 말하기(배포된 사이트를 못 열었으면 그렇게 말한다).
